# 原神跟跑助手

一个可以 **压在原神窗口之上** 的 B 站视频悬浮窗：边跑地图边看攻略，按一下快捷键就能暂停视频，不用 alt+tab 切出去。

## 功能

- **永远置顶**：`alwaysOnTop` 使用 `screen-saver` 层级，压在游戏窗口之上；层级被抢时每 2.5 秒自动夺回
- **全局快捷键**：游戏全屏、鼠标在游戏里也生效，默认 `Alt+空格` 暂停/播放
- **B 站视频**：支持 BV 号、av 号、完整链接、`b23.tv` 短链、带 `?p=3` 的分 P 链接
- **只用网页版播放器**：加载 `www.bilibili.com` 视频页并自动点「网页全屏」，让视频铺满浮窗 —— B 站给站外嵌入的 `player.bilibili.com` 无论登录与否都只有 720P，所以没有保留它
- **纯净模式**：自动隐藏顶栏、右侧推荐、评论区、广告
- **登录 B 站**：标题栏「登录」按钮直接调起扫码窗口，Cookie 存在独立持久化分区里，登录成功自动关窗并按高清重载
- **分 P 切换**：自动读取分 P 列表，下拉选择或快捷键切换
- **鼠标穿透**：开启后点击直接落到游戏里，浮窗只做显示
- **不透明度 / 音量 / 倍速 / 拖动定位 / 拖角缩放**，设置与窗口位置自动记忆

## 快捷键

| 功能 | 默认键 |
| --- | --- |
| 播放 / 暂停 | `Alt+空格` |
| 后退 5 秒 | `Alt+←` |
| 前进 5 秒 | `Alt+→` |
| 上一分 P | `Alt+↑` |
| 下一分 P | `Alt+↓` |
| 隐藏 / 显示浮窗 | `Alt+H` |
| 鼠标穿透 开 / 关 | `Alt+L` |
| 半透明 开 / 关 | `Alt+O` |

全部可在 ⚙ 设置里点击对应的键位重新录制（需要至少一个修饰键，F1–F12 可单独使用）。

**鼠标侧键**：点击任意键位后直接按鼠标侧键，即可把「后退 / 前进」侧键绑上去，录完显示为 `鼠标侧键 ◀` / `鼠标侧键 ▶`。

侧键走的是系统级低级鼠标钩子（`WH_MOUSE_LL`），**不只在本窗口生效**——游戏全屏、焦点在游戏里时照样触发。钩子只做旁观、不吞事件，所以浏览器里侧键的前进后退照常工作。

> 副作用提醒：如果侧键同时被鼠标驱动软件（罗技 G HUB、雷蛇等）绑定了宏，可能会被驱动先截走，触发不到；遇到这种情况把驱动里的绑定清掉即可。


## 登录与画质

B 站现在很多视频必须登录才能完整观看，未登录时播放器只给预览或标清。处理方式：

1. 点标题栏右上角的 **「登录」**（登录后变成一个绿点），弹出 B 站扫码窗口
2. 手机 B 站扫一扫，登录成功窗口会自动关闭
3. 浮窗自动重载当前视频，画质上限随之提升

Cookie 保存在独立的 `persist:bili` 分区，只登录一次，之后每次启动都是登录状态。

**为什么砍掉了嵌入播放器**：`player.bilibili.com` 是 B 站给站外网站用的精简播放器，功能被裁剪，**登录与否都封顶 720P**，左下角还常驻一条「登录观看高清」的引导条 —— 登录了也点不掉，容易让人误以为登录失败。现在统一走 `www.bilibili.com` 视频页：登录后 1080P / 4K / 大会员画质都正常，代价是首屏慢一两秒。

如果登录后仍然提示受限（会员专享、付费内容、充电专属视频等），那属于账号权限问题。

## 让浮窗真的盖住原神

这是关键的一步，**只和游戏的显示模式有关**：

- 游戏内 → 设置 → 图像 → 显示模式，选 **窗口化** 或 **无边框**（不要选「独占全屏」）
- 独占全屏（DirectX exclusive fullscreen）会绕过 Windows 桌面合成，任何外部浮窗都盖不上去，这是系统限制，不是本程序的问题

## 小地图方位标记

把「视频博主正在行进的世界方位」抽成一个角度，在置顶的透明叠加层上画成红色箭头。箭头画在**屏幕坐标系**上（世界方位在屏幕上本来就是固定的），所以无论你自己的小地图是固定北朝上还是随角色旋转都能用。

前提只有一个：**视频里的小地图必须固定北朝上**。如果是随角色旋转的，中央箭头恒朝上，世界方位信息根本不存在。

### 它怎么工作

```
webview 里的 <video>
  → canvas.drawImage 抠出小地图中心一块
  → 径向扫描找青色箭头 → 角度
  → 5 帧内做圆形平滑
  → IPC 只传一个数字 → 叠加层画箭头
```

不截屏、不读游戏进程、不需要任何原生依赖（这点和鼠标侧键不同，侧键那个要 `uiohook`）。识别只在视频有新帧时跑，110ms 一次。

### 两个踩过的坑（都已在真实帧上验证）

1. **箭头的颜色是青蓝色，不是白色**。原神玩家标记约 `rgb(34, 200, 232)`。用「三通道最小值」判白色时它只有 34，会被当成暗色地形 —— 这是识别全错的直接原因。现在用青色判据 `min(g,b) - r`：箭头约 166，草地 / 雪地 / 沙地都是 0。
2. **不能只看「哪个方向最亮」**。雪山、水面同样亮。现在用「亮块对比度」：内圈均值减去同方向外圈均值，孤立亮块才得分。

### 画面布局会变，所以支持多区域

同一个视频里，平时是游戏原生的迷你小地图（左上角，半径约 22px），讲到路线时常常是剪辑放大的地图贴片（半径 80px 以上），两者位置和大小完全不同。单一识别区域必然有一半时间在瞎读。

所以识别区域是**列表**：每帧逐块试，取最可信的一块。标定时框了一处再框另一处，会自动追加（位置重合则替换），最多 4 处。

- 标定结果**按视频记住**，换视频不用重框
- ⚙ → ① 框选视频里的小地图 → 拖动圆环对准箭头支点 → 滚轮调大小 → 完成
- 帧驱动的「有没有小地图」判断：转场、特写、对话时画面里没有小地图，箭头会自动收起，1 秒宽限避免闪烁

### 一个必须接受的局限

这是**够用级**方案，不是导航级：地形干扰、传送锚点图标（也是青色）、角色朝向 ≠ 行进方向（回头打怪时朝向立刻反向），都会让结果偏离。实测在正常游玩画面上误差约 ±10~20°，方向大方向可用，精确定位不行。

要再往上走，得换成小目标检测模型（ONNX 跑箭头）或者用小地图地标做特征配准，那是另一个量级的工程。

## 打包成软件发布

打包后是标准的 Windows 可执行文件，**用户机器上不需要装 Node、Python 或任何运行时** —— Chromium 和 Node 运行时都会被打进产物里。

```bash
# 一次性安装打包工具
npm install -D electron-builder

# 出安装包 + 免安装单文件
npm run dist
```

产物在 `dist/`：

| 文件 | 说明 |
| --- | --- |
| `GenshinRouteBuddy-0.1.0-x64.exe` | NSIS 安装包，可选安装目录、自动建桌面快捷方式 |
| `GenshinRouteBuddy-0.1.0-portable.exe` | 免安装绿色版，双击即用，可放 U 盘 |

国内网络如果卡在下载 `winCodeSign` / `nsis` 这些打包依赖上，加镜像再跑：

```bash
ELECTRON_BUILDER_BINARIES_MIRROR=https://npmmirror.com/mirrors/electron-builder-binaries/ npm run dist
```

### 两个打包需要注意的点

- **`npmRebuild` 必须为 `false`**（已在 `package.json` 里配好）。`uiohook-napi` 带的是 N-API 预编译二进制，跨 Electron ABI 直接可用；一旦让 electron-builder 去 rebuild，它会调用 node-gyp 从源码编译，没装 Visual Studio 的机器会直接报 `Could not find any Visual Studio installation to use`。
- **`asarUnpack` 必须包含 `uiohook-napi`**。原生 `.node` 文件不能留在 asar 压缩包里，否则打包版启动时钩子加载失败、鼠标侧键静默失效。

### 打包版与开发版共用同一份数据

Electron 的 `userData` 目录取的是 `productName`，所以打包前后都是 `%APPDATA%\原神跟跑助手`。设置、窗口位置、B 站登录 Cookie 全部沿用，**不需要重新登录**。

## 目录结构

```
src/
  main.js              主进程：置顶窗口、全局热键、B站解析、设置持久化
  mouse-hotkeys.js     鼠标侧键的全局低级钩子（uiohook）
  preload.js           主窗口 IPC 桥（contextBridge）
  webview-preload.js   注入 B 站页面，直接接管页面里的 <video>
  renderer/
    index.html         界面骨架
    style.css          深色浮窗样式
    app.js             播放器控制、进度条、快捷键与设置面板
```

## 实现要点

- **快捷键能控制 B 站播放器的原因**：B 站播放器在 iframe 里跨域，父页面拿不到 `<video>`；这里把播放器直接作为 `<webview>` 的顶层文档加载，再用 webview 的 `preload` 注入脚本操作 DOM，所以 `play()/pause()/currentTime` 都能直接调用。
- **鼠标侧键为什么不用 globalShortcut**：Electron 的 `globalShortcut` 只接受键盘加速器，不支持鼠标按键。侧键由 `uiohook-napi`（封装 libuiohook）的低级钩子监听，`src/mouse-hotkeys.js` 负责映射；注意 DOM 的 `MouseEvent.button` 与 libuiohook 的 `button` 编号不同（DOM 3/4 → 钩子 4/5），录制与触发之间做了换算。没有绑定任何鼠标键时钩子完全不启动。
- **不抢游戏焦点**：窗口用 `showInactive()` 显示，不会把原神切到后台。
- **层级自愈**：`blur` 事件 + 2.5 秒轮询双重保障，检测到 `isAlwaysOnTop()` 为假就重新置顶。

## 已知限制

- 独占全屏下无法覆盖（见上文，请改窗口化 / 无边框）
- 部分游戏使用 Raw Input 独占键盘，若快捷键失效，在设置里换成别的组合键
- 必须登录才有 1080P/4K，未登录时 B 站自己只放预览或标清（这是账号策略，程序绕不过）
- 网页版首屏比嵌入播放器慢一两秒，换来的是完整画质
